# Blog Post Style Guide

写博客文章时严格遵循以下规范。

## 文件结构

每篇文章一个目录，放在 `src/content/blog/<slug>/` 下，内容文件固定为 `index.md`。图片与 `index.md` 同目录，用相对路径引用（`./image.png`）。

## Frontmatter

```yaml
---
title: "中文标题"
description: "一段话描述文章内容，不超过 100 字"
pubDate: "YYYY-MM-DD"
tags: ["Tag1", "Tag2", "Tag3", "Tag4"]
hexagram: "䷂"    # 可选，易经卦象
element: "metal"   # 可选，water/wood/fire/metal
---
```

## 文章结构

按以下顺序组织：

1. **TL;DR**：紧跟 frontmatter，`**TL;DR:**` 开头，1-3 句话概括全文核心论点
2. **前置知识**：blockquote 格式，包含站内交叉链接
3. **`---` 分隔符**
4. **正文 H2 章节**：每个大章节之间用 `---` 分隔
5. **局限性与权衡**：倒数第二个章节
6. **进一步阅读**：最后一个章节，格式为 `- [标题](URL) — 一句话描述`

## 写作风格

### 语气

- 直接、不废话，像高级工程师给同事解释技术
- 用「你」称呼读者
- 短句为主，一句话一个意思
- 技术但不学术，通俗但不敷衍

### 开头方式

- 用具体场景或数据切入，不要用「随着 XX 的发展」这类套话
- 好的例子：「同一个 AI 模型，同一套基准测试，第一次 42%，第二次 78%」
- 坏的例子：「随着人工智能技术的不断发展，越来越多的开发者开始关注...」

### 段落组织

- 每个章节先讲「是什么」，再讲「怎么用」
- 用具体数字和代码举例，不要空泛描述
- 对比用代码块或列表，不用大段文字
- 实践建议用「应该做的 / 应该避免的」分区

### 代码示例

- 给完整的、可直接使用的代码片段
- 包含注释说明关键点
- 用语言标识（` ```markdown `、` ```bash `、` ```typescript ` 等）

### 跨站引用

- 用相对路径：`[Spec 驱动开发](/blog/spec-driven-development)`
- 在「前置知识」和正文中自然引用相关文章

## 禁止事项

- **不用营销语言**：禁止「竞争壁垒」「无法复制」「零成本」「革命性」「颠覆」
- **不用时间线炒作**：禁止「2023 是 X 年，2025 是 Y 年，2026 是 Z 年」
- **不用 emoji**
- **不用多余形容词**：「精准地」「深刻地」「令人惊叹的」这类词全部删掉
- **不在段落结尾升华**：每段讲完就停，不要加「这才是真正的...」「这正是...的意义所在」
- **不让 AI 生成全文**：文章由人类主导，AI 只做辅助
- **不写废话前置段**：正文第一段直接进入主题，不要铺垫
- **不堆砌引用**：引用名人名言最多一处，且必须与内容直接相关

## 审查清单

写完后检查：

- [ ] TL;DR 是否一句话就能让读者决定要不要继续读？
- [ ] 每个 H2 章节是否都能独立理解？
- [ ] 有没有具体的数字或代码示例？
- [ ] 「局限性与权衡」是否诚实、具体？
- [ ] 「进一步阅读」链接是否有效且有描述？
- [ ] 全文有没有废话？每个段落删掉后文章会不会变差？
